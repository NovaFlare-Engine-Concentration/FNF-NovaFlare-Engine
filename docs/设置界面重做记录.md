# NovaFlare Engine 设置界面重做记录

> 一次完整的设置界面重构记录：**HTML 高保真原型 → Haxe 引擎实现**。
> 写下这份文档的目的：以后（人或 AI）接手这块时，不用重新踩一遍坑。

## 0. 一句话总览

原来的设置界面是「左侧 20% 侧边栏 + 右侧一长条可滚动的分类面板」。这次重做成了：
**左侧竖栏 / 顶部横栏二选一的磨砂侧边栏 + 单面板切换 + 三段式展开动画**，
语言从独立分类改成侧边栏里的下拉列表，返回按钮固定到左下角。

- HTML 原型：`NewOptionState.htm`（单文件自包含，双击即可看效果）
- Haxe 实现：`source/options/` 下 4 个文件
- 图标资源：`assets/shared/images/menuExtend/OptionsState/icons/` 下 12 个 PNG

## 1. 设计规格（HTML 与 Haxe 共用，改的时候两边都要同步）

### 1.1 几何

| 项 | 值 | 说明 |
|---|---|---|
| 竖栏宽 | `17%` 视口宽 | 原为 20%，英文标签只占一半宽、太松 |
| 竖栏展开态 | `18.5%` | 展开时"吸收"面板让出的 1.5% 缝隙 |
| 面板左缘（起点） | `17%` | = 竖栏右缘，面板从这里长出来 |
| 面板左缘（展开） | `20%` | 与竖栏之间留 1.5% 缝隙 |
| 面板右留白 | `8%` | 固定，所以面板最终宽 `72%` |
| 横栏高 | `7vh` | 原 9vh，偏厚 |
| 横栏展开态 | `+1.6vh` | 同样用于吸收缝隙 |
| 横栏与面板缝隙 | `1.6vh` | 面板 top = `bar + 2×gap` |
| 横向左右留白 | `8vw` | **按视口宽度算** |
| 横向底部留白 | **0** | 面板一路贴到屏幕底边 |
| 面板标题栏高 | `10.5%` 视口高 | |

> ⚠️ 踩过的坑：底部留白一度用 `8vh`（1080 下 86px），而左右用 `8vw`（1920 下 154px），
> 差了近一半，看着像"贴到屏幕底"。**横向模式的留白要统一按宽度算。**

### 1.2 磨砂玻璃（第二轮补上的）

Flixel 没有 CSS 的 `backdrop-filter`，只能自己做：

| 项 | 值 | 说明 |
|---|---|---|
| 模糊贴图 | 背景图逐级减半降采样到短边 `64px`，再放大回全屏 | 每级双线性缩小 ≈ 一次 2×2 平均，累积起来近似高斯 |
| 面板玻璃底 alpha | `0.62`（`GLASS_ALPHA`） | 对应 HTML `rgba(44,43,56,.64) → rgba(23,22,30,.74)` |
| 侧边栏玻璃底 alpha | `0.62` | 对应 HTML `--glass-a .60 / --glass-b .70` |
| 切割方式 | `FlxSprite.clipRect` 分别裁成 面板 / 竖栏 / 横栏 三块 | 三块共享同一张模糊贴图 |

> ⚠️ 坑：`setPanelAlpha(a)` 里的 `a` 是「面板整体可见度」，
> 一度被直接写进 `panelBG.alpha`，而 `openVertical/openHorizontal` 传的是 `1`，
> 于是磨砂面板变成了**完全不透明**的色块 —— 实测面板内像素从 `rgb(0,80,255)`
> 变成 `rgb(25,25,31)`，背景一点也透不过来。现在拆成 `GLASS_ALPHA * a`。

### 1.3 动画时长

| 动画 | 分段 | 合计 |
|---|---|---|
| 三段式展开 | ①右缘延伸 200ms → ②一分为二 130ms → ③拉高/铺开 170ms | **500ms** |
| 切换分类时的反向 | ③′ 85ms → ②′ 75ms → ①′ 90ms | **250ms**（= 正向的一半） |
| 竖 ⇄ 横模式切换 | 阶段A 280ms + 阶段B 280ms | **560ms** |
| 折叠一级列表 | 420ms + 逐项 30ms 错开 | 不参与压缩 |

### 1.4 三段动画的语义

**竖向**：从被点菜单行向右延伸（高度=行高）→ 一分为二（面板左移+侧边栏加宽，右缘 92% 不动）
→ 上下缘拉到满高。

**横向**（镜像）：从被点菜单项向下延伸（宽度=项宽）→ 一分为二（面板下移+顶栏加高，下缘不动）
→ 左右缘铺开到 84% 宽。

**切换分类**：先完整反跑 ③②①，再对新分类重跑 ①②③。

## 2. HTML 原型（`NewOptionState.htm`）

### 2.1 为什么是单文件

菜单背景（wtf 模组的 `menuBG.png`，850KB）以 **base64 内嵌**，加上一段小字体，
整个 htm 约 1.2MB，拷到哪都能直接双击打开。注入方式：
先写带占位符的文件，再用 pwsh 把 base64 替换进去（避免让模型直接吐 63 万字符）。

### 2.2 面板几何模型（关键）

面板用 **`left/right/top/bottom`** 定位，而不是 `left/top/width/height`：

- ① 只改 `right`（左缘不动，右缘向右延伸）
- ② 只改 `left`（右缘不动，面板整体右移让出缝隙）
- ③ 只改 `top`/`bottom`

**每条边整场只变一次值** → `transition` 只需在每段序列开头声明一次，
不需要逐段"关过渡 → 强制回流 → 重开过渡"。

> ⚠️ 坑：一开始是逐段重置 transition 的写法，每段会因为强制回流多花 30~100ms 且**逐段累积**，
> 实测三段跑到了 602ms（预算 500ms）。改成"每条边只变一次 + transition 只声明一次"后降到 520ms。

### 2.3 内容在几何动画之后才淡入

面板内容是 20+ 行控件，**首次绘制会占住主线程上百毫秒**。
一开始把"内容淡入"放在 ③ 之前，结果它把 ③ 的定时器整体推后，总时长实测 619ms。
现在内容在几何动画**结束之后**才淡入 —— 空磨砂板升到满高，内容再淡入。

### 2.4 验证方式（重要）

用 **headless Edge + CDP** 做逐帧断言，在页面内用 `requestAnimationFrame` + `performance.now()`
采样几何变化，因此测的是**页面内的真实时间**，不受 CDP 往返延迟影响。

三套脚本（临时文件，未入库）：

| 脚本 | 项数 | 覆盖 |
|---|---|---|
| v6 | 41 | 动画相位/时长、几何、交互、控件 |
| v7 | 16 | 溢出专项：隐藏栏的后代不得渲染到屏幕上 |
| v8 | 28 | 本轮改进：贴底、眨眼、胶囊滑动、频繁点击、栏尺寸一致性 |

**v7 的存在原因**：v6 的 41 项全过，却漏掉了一个真实 bug —— 它只断言了 `sideV`/`sideH`/`panel`
**自身**的矩形，从没检查"屏幕外的容器有没有把子元素漏到屏幕上"。
v7 用两种独立手段兜底：几何法（后代矩形必须完全在屏幕外）+ 命中测试法
（全屏每 40px 撒点跑 `elementsFromPoint()`）。

## 3. Haxe 实现

### 3.1 改动文件

| 文件 | 行数 | 内容 |
|---|---|---|
| `source/options/OptionsState.hx` | ~1060 | 完全重写：两条侧边栏、单面板、三段动画、模式切换、语言、左下角返回、**磨砂层** |
| `source/options/objects/navi/NaviGroup.hx` | ~664 | 重写：整条侧边栏（品牌行/折叠/模式按钮/9 分类/语言下拉）+ `offX/offY` 偏移机制 |
| `source/options/objects/navi/NaviMember.hx` | ~163 | 重写：分类项，竖向/横向两套排布 + 图标 |
| `source/options/objects/backend/StringSelect.hx` | ~238 | 下拉列表底板改成接近不透明的深色（`0x14131D`） |
| `source/options/objects/backend/StringRect.hx` | ~159 | 下拉展开时把列表底板补间到 `alpha 0.96` |
| `source/options/objects/OptionCata.hx` | +4 | 新增 `cataName` 字段 |

**设置项内容完全复用原有体系**：`OptionCata` / `Option` / `groupData/*` / `backend/*` 控件都没动。

### 3.2 关键技术决策（Flixel 侧）

1. **`RoundRect` 有 8 种锚点的 `changeWidth/changeHeight` 补间**，但每段动画改的是不同的边，
   所以最终用一个 `setPanel(x,y,w,h)` 辅助函数 + `FlxTween.num` 驱动手动补间，比内置锚点更可控。

2. **`FlxSpriteGroup.set_x/set_y` 会 `transformChildren` 平移所有成员**（源码 `FlxSpriteGroup.hx:730`）。
   这决定了坐标系方案：移动 `OptionCata` 的 x/y 能带走它下面的所有东西。

3. **但 `Option.update()` 每帧只把 `followX/followY` 从 `follow.mainX/mainY` 同步过来，
   并不重设 `this.x`**（`Option.hx:232`）。所以移动 `OptionCata` 后选项**不会**自己搬位置。
   → 因此采用「**所有分类的 OptionCata 都预先摆在同一个面板内容区，只切换可见性**」，
   动画期间面板是空的，不需要内容跟着动。这也正好和 HTML 的设计一致。

4. **`FlxSpriteGroup` 支持 `clipRect`**（`set_clipRect` 会 transform 到所有子精灵），
   但嵌套组的坐标转换公式可疑（`ClipRect.x - Sprite.x + x`），
   所以内容溢出**改用「可见性裁剪」**：超出面板的 `Option` 直接 `visible = false`，更稳。

5. **兼容性约束（务必保留）**：下面 4 个字段被 5 个控件类依赖，删了会连片编译失败
   ```
   OptionsState.instance.specBG     // BoolButton / NumButton / StateButton / StringRect / StringSelect
   OptionsState.instance.downBG     // 同上
   OptionsState.instance.cataMove   // 需要 .velocity / .inputAllow
   OptionsState.instance.stringCount
   ```
   现在 `specBG` = 面板标题栏区域（跟随面板走），`downBG` = 底部条，
   `cataMove` = 面板内容的滚轮滚动控制器。

### 3.3 交互细节

- **折叠一级列表**：整列向左侧滑出（`translateX`），**高度全程不变**，逐项错开 30ms。
  实现用 `FlxTween` 的 `startDelay`（**不存在 `FlxTimer.start`**，别用）。
- **切换分类时侧边栏不收缩**：`openV/closeV` 带 `keepSb` 参数。首次展开才 17%→18.5%，
  完全关闭才收回 17%。否则每点一次分类侧边栏都会"抽一下"。
- **频繁点击只切到最后一个**：`seqToken` 中断令牌。每次点击一级菜单 `seqToken++`，
  正在播放的序列在每个阶段边界检查令牌、失效就 `return false` 让位。
  实测连点 5 次（间隔 80ms）→ 完整展开次数 = 1，最后一次点击后 ~750ms 稳定
  （若依次播完需要 ~3750ms）。
- **高光交接**：`applyHighlight()` 放在正向动画**开始前**，与新面板延伸同时出现。
- **语言下拉**：列表动态扫描 `language/` 目录（排除 `JustSay`），
  所以是 `Chinese / English / Portuguese (Brazil) / I Dont Like Haxe` 四项，
  mod 加语言目录会自动出现。

### 3.4 坐标系与尺寸约定（第二轮修复，**改 NaviGroup 前必读**）

第一轮实现里，Haxe 侧其实是「照着 HTML 又凭感觉翻译了一遍」，结果踩了两个大坑，
联机截图里表现为「一级菜单不在该在的位置」。

#### 坑 A：`FlxSpriteGroup` 的子元素存的是**屏幕绝对坐标**

```
   add(sprite)  →  preAdd 里做一次  sprite.x += group.x
   group.x = v  →  set_x  →  transformChildren 把每个子元素整体平移 (v - x)
```

所以「用 `group.y` 把整条栏移出屏幕」和「给子元素写绝对坐标」**不能混用**：

| 现象 | 原因 |
|---|---|
| 竖向模式下屏幕顶部浮着一排没有底板的菜单项 | `barH.y = -79` 把底板移走了，但随后 `layoutMembers()` 用绝对坐标把成员摆回了 y≈11 |
| 切到横向后菜单项掉到顶栏外面（y≈119，顶栏只有 76 高） | `toHorizontal()` 里又一次 `barH.y = -79` 再补间回 `0`，这个补间把所有子元素**整体下移了 79px** |
| 横向模式下屏幕中间有一行巨大的 "NovaFlare Eng" | `barV` 只把 `x` 移到屏幕外，巨型品牌名却还在屏幕里 |

**解法**：`NaviGroup` 的 `x/y` 永远固定为 `(0,0)`，改用 `offX / offY` 表示整条栏的
屏幕偏移，所有布局函数写成 `off + 相对位置`，隐藏 = `setOff` 到屏幕外。
`setOff()` 对成员做增量平移（避免打断折叠补间），并同步 `barBG.mainX/mainY`
（`RoundRect` 的子元素是按 `mainX/mainY` 定位的，不同步的话下一次 `changeWidth` 会把底板摆回原点）。

#### 坑 B：竖向分支把「品牌行高 9vh」当成了 1 个单位

竖向栏的 `baseHeight` 传的是 `FlxG.height`（=1080），而代码里乘的却是
**以 9vh 为 1 的比例**：

| 代码 | 本意 | 实际算出来 |
|---|---|---|
| `baseHeight * 0.74` | 6.6vh（分类项高） | **799px** |
| `layoutMembers` 起点 `baseHeight * 1.06` | ≈10.6vh | **1145px（屏幕外）** |
| `baseHeight * 0.49` | 4.4vh（品牌图标/模式按钮） | **529px** |
| `baseHeight * 0.22` | 1.7vh（品牌名字号） | **字号 237** |
| `baseHeight * 0.42` | ≈4.2vh（语言按钮高） | **453px** |
| `layoutLangToggle` 的 `+ (n+1)*baseHeight*0.74` | 9 行菜单之后 | **y ≈ 8240（屏幕外）** |

**解法**：竖向分支全部改成以**视口高**为基准的 vh 常量（`V_MEMBER_H = 0.066` 等，
见 `NaviGroup` 顶部的常量表），横向分支的比例以**栏高**为基准（这部分原来是对的，未动）。

### 3.5 值得记住的坑

| 现象 | 根因 | 解法 |
|---|---|---|
| 点分类时侧边栏"收一下又恢复" | 模式切换时把栏尺寸**无条件**写成了展开态，而面板并没打开 | 按 `wasOpen` 决定：`wasOpen ? bar+gap : bar` |
| 同上（另一个入口） | `toVertical` 不复位侧边栏宽度，残留 18.5% | 同样按 `wasOpen` 复位，并把 `width` 加进过渡 |
| 横向菜单项与面板首帧宽度差 4px | 选中态改了 `padding`，项变宽 | 选中态**不改 padding**，只改背景/边框 |
| 三段动画总超时 | `transitionend` 要等到过渡结束后那一帧才派发，每段多 1~2 帧且累积 | 改用 `setTimeout` 当主时钟 |
| 横排菜单变成一竖列、溢出到屏幕上 | `.members>.inner{flex-direction:column}` **同时命中** `#listV` 和 `#listH` | 收窄为 `#membersV>.inner`，并给 `#sideH` 加 `overflow:hidden` 兜底 |

## 4. 编译与验证

### 4.1 快速类型检查（迭代主力，**1.5 分钟**）

```powershell
haxe export\legacy-gc\windows\haxe\release.hxml
```

`release.hxml` 里本来就带 **`-D no-compilation`**，所以这条命令 = 纯 Haxe 类型检查 +
生成 C++ 源码，**跳过 MSVC**。首轮 ~176s，有缓存后 ~78s。

### 4.2 完整编译（**约 11 分钟**）

```powershell
haxelib run lime build windows
```

> ⚠️ 已知：完整编译在 `src/general/backend/Paths.cpp(423)` 报
> `error C3861: "__hxcpp_gc_request_full": 找不到标识符`。
>
> **根因见 `.workbuddy/memory/MEMORY.md` 的「编译」一节**：引擎的 `GCManager.hx` 调用
> `__hxcpp_gc_request_full` 等 NovaGC 函数，这些**只存在于定制 hxcpp（`hxcpp-novagc`）**里，
> stock hxcpp 4.3.2 必然报这个错。绑定方式：`haxelib dev hxcpp "<proj>/hxcpp"`。
>
> 与设置界面改动**无关** —— `source/general/backend/Paths.hx` 一行没动。

### 4.3 浏览器验证的注意事项

跑 headless 浏览器时**务必用带随机后缀的专属 `--user-data-dir`**，清理时只按该目录路径匹配：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
  Where-Object { $_.CommandLine -like "*$prof*" } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**不要**直接 `Stop-Process msedge` —— 那会把用户正在用的浏览器一起关掉。

## 5. 图标资源

原来的 `icons/` 目录**只有 `specIcon.png`** —— 而 `NaviGroup` 是按 `图标目录 + 分类名.png`
去找图的，也就是说**游戏里分类图标本来就全部加载失败**。这次一并补齐。

12 个 PNG 从 HTML 里的内联 SVG 批量导出（纯白 + 透明底 128×128，游戏里用 `icon.color` 染色）：

```
General.png         User Interface.png   GamePlay.png        Game UI.png
Skin.png            Input.png            Audio.png           Graphics.png
Maintenance.png     NovaFlare Engine.png
ModeHorizontal.png  ModeVertical.png
```

> **文件名必须与分类名完全一致**（含空格，如 `User Interface.png`），因为引擎就是按名字找图的。

导出方法：headless 浏览器里把每个 SVG 画进 `<canvas>` 再 `toDataURL('image/png')`，
一次性批量写盘（脚本直接从页面的 `ICONS` 对象取 path，避免手抄出错）。
