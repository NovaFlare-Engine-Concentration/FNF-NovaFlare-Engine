4交互细则（本原型已实现，可在页面上直接试）

  • 长按 1 秒拖拽：按住列表项 1000ms 不动 → 该行抬起（浮起阴影 + 描边 + 抓取光标）并出现插入指示线；按住期间行底有一条 1 秒进度条作为反馈。拖动到列表上下边缘会以 8px/帧 自动滚动；松手提交排序并弹出「「名称」顺序 #旧 → #新」。
  • 不足 1 秒的两种手势：① 直接松开 = 点击选中该行；② 移动超过 8px = 视为滑动列表/浏览，长按计时被取消。滚轮不受长按影响，随时可上下滚动列表。
  • 超长名字走马灯（只往一个方向）：默认「无缝单向循环」—— 名字复制两份首尾相隔 32px，整条轨道从右往左匀速 32px/s，起点停 0.9s 后再走；走到 文本宽 + 间隔 时第二份恰好接在第一份的位置上，所以循环处看不出接缝、也不会往回滑。演示控制条另有「单程 + 瞬回」（滑到底后 0.6ms 跳回起点，同样不反向）与「省略号」两种对照。
  • 标签筛选：点【已启用】只看启用中的；点【已禁用】只看禁用的；再点一次当前标签 = 取消筛选（两个标签都不点亮，显示全部）。计数实时更新。
  • 右上角启用/禁用：切换后若该 mod 不再属于当前筛选，选中项自动跳到相邻可见行；若该分类已空，列表区显示占位文案。
  • 两焦点区状态机保留：hoveringOnMods ↔ 按钮区；按钮区 Esc 只回列表、列表区 Esc 才退出（与原版一致）。
  • 搜索：匹配 mod 名称与文件夹名，配合标签筛选同时生效。
  • 退出：有改动 → 弹「需要重启游戏才能生效」（waitingToRestart）；无改动 → 回主菜单，若 isFreePlay 为真则回选歌界面并复位该标志。

5落地到 Haxe 的改动清单

  • 重写 source/states/modsMenuState/ModsMenuState.hx：结构与坐标照第 2 节；保留 parseList / saveTxt / reload / moveModToPosition / changeSelectedMod / changeSelectedButton / getButton / updateModDisplayData 与 isFreePlay、waitingToRestart 语义。
  • 窗口条：new WindowControlBar(WindowBarMode.CONSTANT)，把 9 个工具按钮、打开文件夹、搜索框、退出按钮作为外部控件贴到条上（EditorChromeUI 已有 CONSTANT 布局代码可抄：标题块右对齐、按钮列钉右缘 closeX = w − 46）。
  • 搜索框：Flixel 无输入控件，按设置界面重做的老办法——用隐藏的原生 FlxUIInputText 作数据源，自绘外观与命中判定；或先只做「点击后进入输入态」的最简版本。
  • 长按判定：FlxG.mouse.pressed 计时 ≥1.0s 且位移 <8px → 进入拖拽（期间在原位画一条 0→100% 的进度条作反馈）；位移 >8px 或提前松开 → 视为浏览/点击，取消判定。滚轮滚动列表与此判定互不干扰。
  • 走马灯：名字宽度 > 列宽时，只往一个方向平移 —— 建议照原型的「无缝循环」做：同一段文案放两个 FlxText（第二个 x = 第一个.x + 文本宽 + 32），用 FlxTween.num 把两者一起从 0 补间到 -(文本宽+32)，完成后瞬移回 0 重开（onComplete），起点用 startDelay = 0.9s 停留。速度 32px/s、停留 0.9s 直接复用 CharacterEditorMenuBar 的 TEXT_SCROLL_* 常量。
